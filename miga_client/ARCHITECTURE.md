# NETWORK runtime

Рабочее ядро Windows-клиента — `NetworkRuntime`, подключённое к `CMigaClient`. Прежнее ядро удалено из проекта; общие типы tuple, TCP и маршрута, а также парсер пакета находятся в PacketTypes.h. ConfigManager только загружает конфигурацию, индексы маршрутизации принадлежат новому ядру. Wire format и Linux-сервер не изменены.

Объявления классов находятся в include, реализации — в src с той же структурой подкаталогов. Внутреннее состояние NetworkRuntime::Impl объявлено в src/NetworkRuntimeImpl.h, методы определены в src/NetworkRuntime.cpp. Шаблонные методы остаются в заголовках для инстанцирования вызывающим кодом.

## Потоки и владение

| Поток | Операции |
| --- | --- |
| NETWORK | Overlapped-приём до 64 пакетов, разбор заголовков, поиск готового маршрута, состояние TCP/UDP, FIFO ожидающих пакетов, MSS, XOR+SWAP, UDP-обёртка и фрагментация, восстановление ответов, контрольные суммы, обе асинхронные отправки и их завершения. Применение подготовленной конфигурации. |
| SOCKET | Overlapped-приём до 64 событий, получение дескриптора экземпляра процесса, обновление владельцев по EndpointId/Timestamp, CLOSE, уведомление NETWORK о затронутых портах. |
| Классификатор | Определение имени по сохранённому экземпляру процесса, выбор процесса → статического IP → IP явного доменного правила, DNS-запросы/ответы, вспомогательные запросы, TTL и соответствия адресов между серверами. Чтение новой конфигурации. |
| Windows API | Подготовка транспортов при reload, GetBestRoute2/GetIpInterfaceEntry, обновление кеша исходного адреса/MTU, снимки TCP и проверка экземпляров процессов для давно неактивных записей. |
| Обслуживание | Периодические ограниченные задания очистки и публикации диагностики; изменяемые таблицы очищает владеющий ими поток порциями до 128 записей. |
| Logger | Запись ограниченной очереди сообщений в файл. Формирование сообщений остаётся у вызывающих потоков; при INFO/WARNING быстрый путь не формирует попакетные сообщения. DEBUG включает packet_received/route_lookup и socket_event с QPC-временем и TCP sequence/ACK. |

Стартовые снимки TCP/UDP и первоначальная подготовка транспортов выполняются до NETWORK-перехвата. SOCKET уже подписан и принимает события во время снимка. Существующие TCP-сеансы сохраняют прямой маршрут. Системные вызовы подготовки могут задержать запуск; уже выполняющийся Windows API нельзя отменить при Stop.

## Быстрый путь

NETWORK владеет двумя приёмными буферами по 256 КиБ и заранее запускает следующий приём. Известный прямой пакет попадает непосредственно в накопитель асинхронной отправки. Известный туннельный пакет преобразуется непосредственно в приёмном буфере и передаётся в накопитель внешних датаграмм. Межпоточной очереди этих пакетов и отдельного туннельного потока нет. Накопленные отправки завершаются в конце полученной пачки без ожидания следующей.

IPv6, неподдерживаемые протоколы и DHCP 67/68 исключены фильтром и остаются в стеке. Private, loopback, link-local, multicast и broadcast IPv4 идут напрямую. NETWORK открыт без `WINDIVERT_FLAG_FRAGMENTS`: входящие фрагменты собирает Windows до перехвата. Это поведение требует проверки с реальным драйвером на целевой машине.

Обе отправки используют отдельные пулы по 32 overlapped-операции. Буферы, адреса и OVERLAPPED живут до завершения/отмены. Насыщение пула учитывается в `send_pool_full`; гарантий доставки при перегрузке нет.

## Состояние и ожидания

- `SocketDirectory`: до 8192 владельцев, индекс по протоколу/локальному порту, shared_mutex для коротких чтений и изменений. Записи неизменяемы, активность и границы жизни атомарны. При заполнении сначала вытесняется самый давно закрытый владелец; при отсутствии закрытых записей новый владелец не добавляется. Это не удаляет сохранённый TCP-маршрут.
- `FlowTable`: до 65536 полных tuple, единственный владелец NETWORK. На пакете обновляется активность, но таймер не переставляется. Версии портов позволяют обходиться без поиска владельца для обычного пакета известного соединения. Обратная DNS-подмена индексируется по серверу и полному tuple, а не глобально по IP. Неоднозначное совпадение двух преобразованных tuple не разрешается созданием второго маршрута.
- CLOSE оставляет владельца на 30 секунд. TCP-маршрут независим от удаления владельца: ACK и SYN с сохранённым sequence продолжают использовать маршрут. Если SYN использовал BIND, единственный точный CONNECT того же экземпляра процесса между BIND и SYN уточняет владельца без смены маршрута и поколения. Ненулевой ParentEndpointId должен совпасть с BIND. Для нового подключения после SYN смена EndpointId означает новое поколение даже с тем же sequence. Ожидание другого SYN не блокирует ACK сохранённого поколения.
- TCP: 124 минуты простоя, после RST/двух FIN — 4 минуты. UDP: 20 минут. Открытый давно неактивный TCP проверяется в Windows. Ответ проверки сверяется по ID, попытке, активности и CLOSE/cutoff; ошибка снимка не означает отсутствие соединения. Повторная успешная проверка через 60 секунд, ошибка/непереданное задание — через 30 секунд.
- Неизвестный владелец: до 1024 пакетов / 4 МиБ, индивидуальный срок 5 секунд. Новое соединение без сохранённого маршрута после срока отправляется напрямую. Неопределённое новое поколение известного TCP и UDP с прежним туннельным маршрутом отклоняются. Решения классификатора проверяются повторно по текущему владельцу и версии конфигурации.
- Временно недоступный исходный адрес/MTU: отдельное ограниченное ожидание до 1024 пакетов / 4 МиБ / 5 секунд. Оно сохраняет порядок пакетов одного сервера; готовые серверы продолжают работу.
- Межпоточные очереди передают задания/результаты: NETWORK 2048, классификатор 1024, SOCKET и Windows по 128. DNS-пакеты также проходят классификатор. Очереди ограничены числом заданий; эти лимиты не являются общим пределом памяти процесса. NETWORK не ждёт свободного места при передаче задания. При временном насыщении классификатора запрос повторяется.

Блокировки очередей освобождаются до выполнения задания. Под блокировкой SocketDirectory не отправляются задания и не вызывается Windows API. Таблицы маршрутов и DNS не имеют вложенных межпоточных блокировок: каждый набор изменяет только его владелец. PacketBufferPool используется только для пакетов, которым требуется отдельное время жизни.

## DNS и reload

Прямой входящий DNS-ответ возвращается в стек сразу и без изменений. При наличии явных доменных правил его копия передаётся классификатору для изучения адресов; отказ этой очереди фиксируется как dns_observation_rejected и не отбрасывает сам ответ.

Правило приложения направляет DNS через его сервер, но не создаёт глобальное правило по полученному IP. Глобальные IP возникают только из DNS-ответа с именем вопроса, соответствующим явному redirect_domains. Основной и вспомогательные запросы получают уникальные wire ID; основной ответ восстанавливает ID приложения, вспомогательные ответы не попадают в стек. Соответствия учитывают несколько A-записей, порядок ответов и TTL обеих сторон. До 8192 незавершённых wire ID, до 65536 динамических записей и до 65536 соответствий адресов; переполнение отражает `dns_capacity_exceeded`.

Reload подготавливает конфигурацию и транспорт до публикации. Неизменившиеся IP/порты/ключи сохраняют транспорт и стабильный ID. NETWORK приостанавливает обработку новых пачек и ждёт завершения старых отправок, затем атомарно публикует конфигурацию. Старые результаты классификации не применяются к новой версии. Удалённый транспорт делает существующие маршруты недоступными, без автоматического перехода напрямую. Уровень логирования меняется без повторного открытия и обрезания файла.

Stop будит ожидания, закрывает межпоточные очереди, завершает потоки, отменяет и завершает I/O до закрытия WinDivert handle. При необработанной ошибке NETWORK/SOCKET остальные потоки получают сигнал остановки; служба выходит из рабочего цикла без автоматического перезапуска.

## Диагностика и проверка

`runtime_queue_delay` показывает ожидание задания от постановки до извлечения, порог 100 мс, отдельно для каждой очереди. Оно не включает пятисекундное ожидание владельца. `batch_processing` относится к обработке принятой NETWORK-пачки. `runtime_drop` содержит причину и число отказов; время префикса — первый отказ этой группы. `send_pool_full` считает отклонённые операции, которые могут содержать несколько пакетов. `route_created`, `packet_received`, `route_lookup`, `socket_event`, `pending_timeout` и `runtime_counters` доступны в DEBUG. `socket_owner_capacity` сообщает об отказе добавить владельца при заполнении таблицы открытыми записями. Старые `event_queue_delay type=NETWORK` и `tunnel_queue_full` относятся к прежнему PacketMonitor.

Тесты и команды — в [tests/README.md](tests/README.md). Проверки с подменёнными WinDivert API не подтверждают работу настоящего драйвера, стартовые гонки снимка, фактическую доставку или выигрыш производительности. Для сравнения нужны одинаковые живые прогоны UDP, churn и обычного TCP/DNS-трафика.
